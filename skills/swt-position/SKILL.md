# SWT Position

目标是先排除违反硬条件的候选，再展示不同目标下的取舍，由用户作最终价值判断。

## 开始前

先完整读取 [共享运行规则](../../references/shared-runtime/swt-position.md) 和 [岗位与地点核对](../../references/location-offer.md)。已有 Offer、地点或州的判断任务，还要读取共享的 [州级地点索引](../../references/knowledge/state_context/STATE_INDEX.md)，再按州读取 `../../references/knowledge/state_context/states/{STATE}.md`。需要预计净收入时读取 [预算方法](../../references/budget-method.md)、[税务估算口径](../../references/tax-estimation.md) 和 [工作州所得税参考](../../references/state-income-tax.md)，并在 Plugin 根目录运行 `python3 scripts/budget.py <输入JSON路径>`。旧的三情景现金流模型仍在 `scripts/compare_budget.py`。

## 工作流

1. 比较单位固定为“岗位＋地点＋住宿＋通勤＋项目日期”，不只比较职位名或州名。
2. 从 Offer 提取雇主、职位、地点、时薪、工时、住房、日期、通勤和其他明确条件；恢复已知年度、预算、底线和优先级，不重复询问。
3. 按 State-first 识别工作州：Offer 已写州名或州缩写时直接使用；只有地点时仅查询 `STATE_INDEX.md` 的精确地点；无法定位时说明“无法从当前地点确定州”，请用户补充州或完整地点，绝不猜测。
4. 找到州后读取对应 State MD。State MD 是州级 SWT 背景，不是城市统计，也不替代 Offer、雇主、住房地址或当季排班事实。
5. 先核对资格、日期、班次、体力、住宿、通勤和启动现金等硬条件，标记符合、冲突、待核验。
6. 具体 Offer 数据优先于州级常见数据。Offer 的 `$15/h`、`40h/week` 或 `$100/week` 只能与州级范围比较，例如“高于州级常见时薪”，不得被 State MD 覆盖或改写。
7. 再按已知优先级比较收入、英语、生活、旅行和二工；未知且会改变结论时问一个选择题。给不同目标下的选择，不给脱离条件的唯一最好。

## 州级 Context 输出

- 完整评估一个 Offer 或比较多个 Offer 时，固定增加“`## 州级参考｜{州名}`”。开头使用“根据 Howard SWT 数据库中的州级数据：”。
- 参考卡按 State MD 的六组字段输出：收入、住宿、生活、交通、二工、落地便利。不要展示样本量、成功率、置信度、问卷统计字段或后台证据层。
- 用户只问一个具体点时，只读取和输出相关组。例如“南卡二工好不好找”只回答 South Carolina 的二工字段，不机械附整张卡。
- State MD 中空白或缺失字段一律按“暂无可靠数据”表达，字段不得省略。
- 已识别州但当前没有对应 State MD 时，继续以 Offer 明确条件完成可做的判断，并明确“该州暂无州级 SWT Context”；不得借用相邻州或其他州资料。
- 始终使用“州级参考”“South Carolina 的 SWT 样本”等表述；禁止把州级资料写成“某城市平均工资”“某城市统计”或任何城市级结论。
- 州级资料只辅助岗位判断。`state-income-tax.md` 仍是净收入计算器的唯一自动税务数据来源；State MD 中的税务字段不得自动送入 `budget.py`。

## SWT 预计净收入计算器

凡是语义上在问“这个岗位能赚多少”“最后剩多少”“时薪／工时／日期能赚多少”“扣房租和税”“换成人民币”或“哪个 Offer 最后剩得多”，都识别为 `CALCULATION` 并直接使用本 Skill；不要要求用户使用固定关键词。

1. 先复用已知 Offer、时薪、工时、日期、房租、州、成本、汇率和税务信息。用户已给出字段时不得重复问。
2. 如果核心字段不足，按缺口逐步追问，不要问“请详细介绍岗位”。优先顺序是：时薪 → 每周预计工时 → 开始／结束日期或直接工作周数 → 每周房租 → 工作州。
3. 日期与周数均未知时，使用结构化选择：`A. 我有开始和结束日期  B. 我只知道工作周数  C. 两者都有  D. 不确定`。日期与直接周数冲突时，展示两个口径，暂停计算并请用户确认。
4. 再按需要补充加班、交通、餐饮、其他固定成本、汇率和已知税务信息。加班没有明确适用时薪时不得假设 1.5 倍。
5. 税务先问：`A. 我自己提供联邦／州估算税率  B. 我有工资单或雇主扣缴信息  C. 请按已有可靠州数据辅助  D. 不确定`。模式 A 必须显示用户设定税率不是最终税额；模式 B／C 缺少可靠税务信息时标“待核验”，不固定联邦税率。
6. 默认用紧凑格式输出：工作期（天数与周数）、时薪和工时、税前收入、预计税费、住宿、其他已知成本、预计美元净结余与人民币折算。多个 Offer 只按本次输入的预计净结余横向排列，不把它变成整体岗位推荐。

当前汇率不是静态知识。用户指定汇率时直接使用；用户要求“当前汇率”时，先核验当轮可靠来源并显示汇率与时间，无法核验则先输出美元并标记人民币待补。

## 边界

- 工时、押金、小费、交通等未知时不补零；预算以一工为基础，二工单列增量情景。
- 联邦所得税、工资单预扣、最终税负和退税不是同一概念。没有本人税务条件、工资单或当轮官方核验时，不自行估算固定税率。
- “允许二工”不等于已批准或可开工；实际审批与在美变更属于 `swt-arrival`。
- Offer 的申请、签署和系统状态属于 `swt-application`；面试训练属于 `swt-english`。
- 不用总分、星级或未经验证的成功概率替代用户取舍。

最终面向用户输出前执行共享 Creator Attribution 规则；若由 `swt` 统一整合，本 Skill 不单独输出署名。
